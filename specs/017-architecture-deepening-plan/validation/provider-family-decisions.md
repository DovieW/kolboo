# Provider-Family Seam Decisions

Provider-family seams are only real when at least two concrete adapters use the seam and the deletion test shows caller complexity would otherwise reappear.

## WebSocket transport policy

| Field                           | Value                                                                                                                                                                                                                                                                         |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Concern                         | Realtime WebSocket connection policy for streaming STT providers                                                                                                                                                                                                               |
| Candidate adapters              | OpenAI Realtime, Deepgram, ElevenLabs, Speechmatics, AssemblyAI, and Fireworks                                                                                                                                                                                                 |
| Current duplication/caller pain | Realtime providers all need the same lower-level behavior for manual HTTP proxy CONNECT, manual `no_proxy` bypass, trusted CA certificates, and invalid-cert override handling, while their URLs, headers, auth, and protocol state machines remain provider-specific.          |
| Deletion test result            | Deleting `stt::websocket_transport::connect_ws_with_transport_policy(...)` would push proxy/tunnel/TLS behavior back into every realtime STT Adapter or recreate the old silent gap where WebSocket streaming ignored configured transport settings that batch HTTP calls used. |
| Decision                        | Implement                                                                                                                                                                                                                                                                      |
| Target files if implemented     | `app/src-tauri/src/stt/websocket_transport.rs`, `app/src-tauri/src/stt/streaming.rs`, realtime STT adapters under `app/src-tauri/src/stt/**`, `specs/018-remaining-module-deepening/validation/seam-evidence.md`                                                              |
| Characterization tests          | `app/src-tauri/src/stt/websocket_transport.rs` unit tests cover exact/suffix/port and wildcard `no_proxy` matching, unsupported HTTPS proxy diagnostics, and local loopback manual HTTP proxy CONNECT request shape with Basic auth.                                         |
| Redaction/privacy checks        | Tests use synthetic hosts and credentials only. Production code never logs proxy passwords or API keys; unsupported HTTPS-proxy diagnostics mention only the capability gap, not configured secrets.                                                                            |
| Notes                           | This Seam owns connection transport only. Provider protocol state machines, headers, request/response frames, and partial transcript semantics stay in concrete STT Adapters.                                                                                                  |

## LLM provider client configuration

| Field                           | Value                                                                                                                                                                                                                                                     |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Concern                         | Shared HTTP client/model/base-url/timeout/request-log-store setup for LLM adapters                                                                                                                                                                         |
| Candidate adapters              | OpenAI, Anthropic, Cohere, Gemini, Fireworks, Groq, Cerebras, and Ollama                                                                                                                                                                                   |
| Current duplication/caller pain | Multiple LLM adapters expose similarly named builder methods, but those methods currently remain adapter-local and are mostly called from provider construction paths that still need provider-specific defaults and request/response types.                 |
| Deletion test result            | Preflight did not justify a new shared Interface in this slice: a common config wrapper would mostly forward fields back into each adapter, and deleting it would not yet reintroduce duplicated caller policy because the caller-specific factories remain small. |
| Decision                        | Defer                                                                                                                                                                                                                                                     |
| Target files if implemented     | None for this slice. Reopen with a small `llm/client_config.rs` only if at least two adapters need a new shared concern such as timeout/cert/proxy/request-log policy that otherwise requires repeated edits.                                             |
| Characterization tests          | Existing provider constructor/unit tests plus future targeted tests for timeout enabled/disabled behavior, base URL override, request-log-store propagation, model defaulting, and no secret logging before any extraction.                                  |
| Redaction/privacy checks        | Any future implementation must keep API keys in adapter request headers only and avoid logging secrets while moving shared HTTP-client configuration.                                                                                                      |
| Notes                           | Do not create a generic cross-family `ProviderAdapter`. Provider request formats and structured-output behavior stay with concrete LLM Adapters unless a separate two-adapter proof passes.                                                                 |

## STT streaming transcript event parsing

| Field                           | Value                                                                                                                                                                                                                                 |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Concern                         | Parsing provider-specific streaming frames into normalized partial/final transcript events                                                                                                                                             |
| Candidate adapters              | OpenAI Realtime, Deepgram, ElevenLabs, Speechmatics, AssemblyAI, and Fireworks                                                                                                                                                         |
| Current duplication/caller pain | Adapters all emit `PartialTranscript`-style events, but the JSON frame shapes, finality rules, timestamps, endpointing behavior, and close semantics are provider-specific.                                                             |
| Deletion test result            | A broad parser Interface would either erase provider-specific protocol detail or become a pass-through around each adapter's frame loop. Pure parser Modules can still be extracted per provider when they make individual adapters deeper. |
| Decision                        | Defer                                                                                                                                                                                                                                 |
| Target files if implemented     | None for this slice; keep provider protocol state machines in concrete STT Adapters and shared session lifecycle in `app/src-tauri/src/stt/streaming.rs`.                                                                               |
| Characterization tests          | Future parser extractions should use synthetic provider frames only; no network/API-key tests.                                                                                                                                         |
| Redaction/privacy checks        | Synthetic frame tests must avoid real transcripts unless fixtures are intentionally fake.                                                                                                                                               |
| Notes                           | Reopen only for a narrow normalized-event parser that reduces repeated frame-to-event logic without moving connection/session policy out of `streaming.rs` / `websocket_transport.rs`.                                                |

## LLM structured output fallback/parsing

| Field                           | Value                                                                                                                                                                                                                                              |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Concern                         | JSON Schema structured-output fallback and response parsing for LLM providers                                                                                                                                                                      |
| Candidate adapters              | Current `LlmProvider::complete_json_schema(...)` default plus provider-specific overrides such as OpenAI/Cohere/Gemini where supported                                                                                                             |
| Current duplication/caller pain | The trait method is already the load-bearing Interface for callers. The remaining provider-specific pieces are capability/API-shape decisions rather than repeated caller complexity.                                                               |
| Deletion test result            | Extracting another provider-family Seam now would wrap the existing trait method and make callers learn an extra concept. Deleting the trait method would reintroduce structured-output branching at call sites, so the current seam remains correct. |
| Decision                        | Defer                                                                                                                                                                                                                                             |
| Target files if implemented     | None for this slice.                                                                                                                                                                                                                              |
| Characterization tests          | Existing and future `complete_json_schema(...)` tests should cover schema prompt fallback and provider override parsing with synthetic payloads.                                                                                                    |
| Redaction/privacy checks        | Structured-output tests should use fake prompts/payloads and must not log user prompt bodies or API keys.                                                                                                                                          |
| Notes                           | Reopen only if JSON extraction/parsing helpers are duplicated across two provider overrides and can move without changing the caller-facing trait.                                                                                                   |

## OCR provider adapter

| Field                           | Value                                                                                                                                                                             |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Concern                         | OCR provider abstraction across multiple OCR backends                                                                                                                             |
| Candidate adapters              | Current OCR implementation only                                                                                                                                                   |
| Current duplication/caller pain | There is not yet a two-adapter proof; existing OCR work is about OCR Session ownership and usage policy rather than provider-family variation.                                     |
| Deletion test result            | A new OCR provider Interface would be hypothetical and deleting it would not reintroduce duplicated adapter logic today.                                                           |
| Decision                        | Defer                                                                                                                                                                             |
| Target files if implemented     | None for this slice.                                                                                                                                                              |
| Characterization tests          | Reopen when a second OCR adapter exists; tests should use fake image/payload fixtures and no API keys.                                                                             |
| Redaction/privacy checks        | OCR payloads may include screenshots or extracted text; any future provider seam must preserve existing request-log redaction and avoid storing image bytes in diagnostics.         |
| Notes                           | Keep OCR session/task ownership in `pipeline/ocr_session_state.rs` and `ocr_session.rs`; do not add provider-family seams before the second Adapter exists.                        |

## Managed-mode adaptation

| Field                           | Value                                                                                                                                                                                                      |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Concern                         | Managed-mode provider adaptation                                                                                                                                                                           |
| Candidate adapters              | Personal license managed routing and Enterprise policy managed routing                                                                                                                                     |
| Current duplication/caller pain | The shared behavior is already localized in `resolve_provider_mode(...)`; provider constructors consume the resolved runtime mode rather than duplicating tier/policy checks.                              |
| Deletion test result            | Additional managed-mode seam in `managed_inference/mod.rs` would be pass-through: deleting it would not reintroduce duplicated provider logic because the existing resolver remains the load-bearing seam. |
| Decision                        | Defer                                                                                                                                                                                                      |
| Target files if implemented     | None for this slice; keep `app/src-tauri/src/pipeline/config.rs` as the current seam.                                                                                                                      |
| Characterization tests          | `app/src-tauri/src/tests/managed_personal_tests.rs` (`managed_mode_characterization_covers_personal_and_enterprise_adapters`, `managed_mode_characterization_preserves_byok_fallbacks`)                    |
| Redaction/privacy checks        | No request payloads or secrets are handled by this resolver; managed tokens remain outside the tests.                                                                                                      |
| Notes                           | Reopen only if another caller starts duplicating tier/policy/eligibility routing outside `resolve_provider_mode(...)`.                                                                                     |

## Provider error classification

| Field                           | Value                                                                                                                                                                                                                                                    |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Concern                         | Retry/auth/quota/timeout/user-visible failure classification                                                                                                                                                                                             |
| Candidate adapters              | STT HTTP providers that surface status/body as `SttError::Api(...)` (e.g. Groq, Deepgram, OpenAI-compatible providers)                                                                                                                                   |
| Current duplication/caller pain | Deterministic retry classification is already centralized in `stt::retry::is_retryable_error(...)`; provider adapters still need provider-specific status/body extraction.                                                                               |
| Deletion test result            | A broader provider-family error seam would either wrap only one real shared policy (`is_retryable_error`) or erase provider-specific response parsing. Deleting such a new seam would not simplify current callers beyond the existing retry helper.     |
| Decision                        | Defer                                                                                                                                                                                                                                                    |
| Target files if implemented     | None for this slice; keep provider-specific extraction in adapters and shared retry classification in `app/src-tauri/src/stt/retry.rs`.                                                                                                                  |
| Characterization tests          | `app/src-tauri/src/tests/stt_integration_tests.rs` (`provider_error_classification_preserves_retryable_status_semantics`) plus existing provider non-success tests for Deepgram, AssemblyAI, Groq, Fireworks, Aquavoice, ElevenLabs, and Whisper Server. |
| Redaction/privacy checks        | Tests use synthetic status/body strings only; no API keys or user content.                                                                                                                                                                               |
| Notes                           | Reopen when at least two adapters can share response parsing without losing provider-specific error detail.                                                                                                                                              |

## Provider request metadata and redaction

| Field                           | Value                                                                                                                                                                                                                                                             |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Concern                         | Request metadata, diagnostics, and redaction                                                                                                                                                                                                                      |
| Candidate adapters              | STT, LLM, router, Quick Ask/Quick Replace, and OCR request-log payload fields                                                                                                                                                                                     |
| Current duplication/caller pain | Secret redaction and user-content stripping are already centralized in `request_log.rs`; adapters only attach bounded payload previews.                                                                                                                           |
| Deletion test result            | A new STT-provider metadata seam would be pass-through unless it replaced the existing request-log sanitizer. Deleting the existing sanitizer would reintroduce redaction at every payload field, so it remains the correct seam.                                 |
| Decision                        | Defer                                                                                                                                                                                                                                                             |
| Target files if implemented     | None for this slice; keep `app/src-tauri/src/request_log.rs` as the sanitizer/metadata seam.                                                                                                                                                                      |
| Characterization tests          | `app/src-tauri/src/tests/request_log_schema_tests.rs` (`request_log_redaction_preserves_provider_metadata_but_removes_secrets_and_payloads`, `request_log_preserves_strategy_independent_router_decision_diagnostics`) plus existing request-log redaction tests. |
| Redaction/privacy checks        | Authorization/token-like values are redacted, provider/model metadata remains, and user text/provider payloads are stripped by retention helpers.                                                                                                                 |
| Notes                           | Reopen if adapter-specific payload capture begins duplicating sanitizer logic outside request-log helpers.                                                                                                                                                        |

## Provider cost reporting

| Field                           | Value                                                                                                                                                                                                                                                                                                         |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Concern                         | Cost Reporting event assembly from provider telemetry                                                                                                                                                                                                                                                          |
| Candidate adapters              | OpenAI and Groq for the two-adapter proof; Gemini, Anthropic, Fireworks, Deepgram, Aquavoice, AssemblyAI, Speechmatics remain provider-specific branches behind the same reporting Interface.                                                                                                                  |
| Current duplication/caller pain | `stats.rs::emit_cost_events_for_current_request(...)` previously owned request-log field selection, provider response parsing, provider duration fallbacks, token mapping, and provider estimator dispatch before appending stats events.                                                                       |
| Deletion test result            | Deleting `cost/reporting.rs` reintroduces the long provider-specific telemetry/estimation match into `stats.rs` for every stats emission path. Keeping pricing tables/formulas in provider modules avoids a false generic estimator seam while still removing caller complexity from Stats.                    |
| Decision                        | Implement                                                                                                                                                                                                                                                                                                     |
| Target files if implemented     | `app/src-tauri/src/cost/reporting.rs`, `app/src-tauri/src/stats.rs`, `app/src-tauri/src/telemetry.rs`, `specs/018-remaining-module-deepening/validation/seam-evidence.md`                                                                                                                                     |
| Characterization tests          | `app/src-tauri/src/cost/reporting.rs` unit tests (`openai_and_groq_llm_reports_share_usage_mapping_without_sharing_rates`, OpenAI STT duration fallback, Groq STT duration pricing, Anthropic cache token mapping) plus prior `provider_family_cost_estimators_preserve_provider_specific_rates`.             |
| Redaction/privacy checks        | Cost Reporting consumes provider response JSON already captured by request logs and tests use synthetic usage/duration payloads only. User text and request payload stripping remain in `request_log.rs`; Telemetry Mapping passes only request id, provider/model metadata, and provider response telemetry. |
| Notes                           | This is not a generic pricing-table abstraction. The shared seam is event-level Cost Reporting assembly; provider-specific formulas stay under `cost/**`.                                                                                                                                                      |
